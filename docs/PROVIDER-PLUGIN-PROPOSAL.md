# CR-006·CR-007 PRD 개정 제안: 제공자 확장과 플러그인 관리

작성일: 2026-10-03. 상태: **승인됨(2026-10-03)**, PRD 11절 편입. CR-004는 A안으로 결정. 기존 SRC/REL/MOD/CTX 승인 범위와 미완료 요구는 유지한다.

## 1. 사용자 요구
- CR-006: ChatGPT/Codex·Claude 외에도 사용자가 구독 중인 다른 AI 제공자·모델을 언제든 쉽게 추가하고, 시기와 분야별로 가장 적합한 모델을 작업에 적용한다.
- CR-007: 토큰 절약, 결과물 품질(디자인 등) 향상 같은 서드파티 플러그인을, 손해 없이 이득이 확인될 때만 쓴다. 작업마다 가장 필요하고 우수한 조합을 적용하고, 명확히 더 나은 대체가 있으면 도태된 플러그인은 제거하고 대체를 추천한다.

## 2. 확인된 사실 (2026-10-03)
- 현재 코드는 제공자가 `codex|claude` 두 값으로 저장소·실행기·배정·화면 전반에 고정되어 있다. 새 제공자를 추가하려면 제공자 계약(어댑터)이 먼저 필요하다.
- SKILL.md 기반 Agent Skills 공개 표준(2025-12 공개)은 Codex CLI, Claude Code, Gemini CLI, GitHub Copilot, Cursor 등 약 40개 도구가 지원한다. 도구 연결은 MCP가 공통 표준이다. 따라서 플러그인은 제공자별 형식이 아니라 이 공개 표준을 기준으로 관리할 수 있다.
- 구독 기반 접근 경로는 자주 바뀐다. 예: 외부 보도에 따르면 Google은 2026-06-18 구독 계정의 hosted Gemini CLI를 Antigravity CLI로 옮겼다(공식 확인 필요). 구독 로그인은 보통 브라우저 인증이 필요하고, 헤드리스용 대안은 유료 API 키인 경우가 많다.
- 플러그인 공급망 위험이 크다. 2026년 공개 감사에서 스킬 3,984개 중 1,467개 악성 payload가 보고되었고, 마켓플레이스 대량 오염 사례가 있었다. MCP 서버에는 코드 서명 표준이 없다. 악성 스킬은 실행 에이전트의 파일·자격증명 권한을 그대로 갖는다.

## 3. 판단
- **CR-006은 가치가 높다.** 모델 성능 우열이 시기·분야마다 바뀌므로 제공자를 어댑터로 분리하면 접근 경로 변경도 해당 어댑터만 고치면 된다. 다만 "언제든 추가"는 각 제공자가 **구독 인증으로 프로그램 실행이 가능한 공식 CLI/에이전트**를 제공할 때만 가능하다. 유료 API 키 경로는 기존 원칙대로 쓰지 않는다. PC가 꺼져도 동작하는 클라우드 실행은 해당 제공자가 클라우드 에이전트 제품을 제공할 때만 가능하다.
- **"가장 우수한 모델" 자동 판단에는 근거가 필요하다.** 공개 벤치마크는 후보 신호일 뿐이고, 작업군별 정상 작업 관측과 독립 품질 검토, 사용자가 허용한 비교 평가가 근거가 된다. 현재 추가 평가 예산은 0이고 CR-004(실행 경로 기반 비교 단위)는 미결정이다. 제공자가 늘수록 동일 조건 비교가 중요하므로 CR-004 결정이 함께 필요하다.
- **CR-007은 조건부로 가치가 있다.** 공개 표준 덕분에 한 번 검증한 스킬을 여러 제공자에서 재사용할 수 있다. 그러나 "손해 없이 긍정적 영향만"과 "오류 가능성 없음"은 사전에 보장할 수 없다. 효과는 작업 유형마다 다르고, 토큰 절약형 도구는 품질을 떨어뜨릴 수 있으며, 보안 위험이 실재한다. 따라서 **허용 출처·버전 고정·권한 최소화·실측 근거·사용자 승인**을 갖춘 관리 방식으로만 도입한다. 자동 설치는 하지 않고, 도태는 자동 제외 후 삭제를 추천하며 실제 삭제는 사용자 확인으로 한다.
- 디자인 품질을 사람 수준으로 높이는 플러그인은 허용 대상이다. 다만 논문·지원서 등 제출물의 AI 작성 사실을 탐지 회피 목적으로 숨기는 용도는 기관 규정과 충돌할 수 있어 대상에서 제외한다.

## 4. 요구사항과 완료 기준
|ID|요구사항|완료 기준|
|---|---|---|
|PRV-01|제공자 등록 계약|선언형 manifest + 어댑터만으로 제공자를 추가. 기존 Codex·Claude도 같은 계약으로 옮기고 동작 동일(기존 전체 테스트 통과)|
|PRV-02|구독 인증만 허용|공식 CLI/앱의 구독 로그인 경로만 등록. API 키·유료 과금 경로는 거부. 인증 만료·경로 변경 시 해당 제공자만 '연결 필요'로 표시하고 다른 작업에 영향 없음|
|PRV-03|실행 위치·능력 선언|로컬(PC 필요)/클라우드, 파일 산출, 결과 콜백, 중단 보장 수준, 사용량 보고 여부를 capability로 선언. 검증되지 않은 capability는 배정에 쓰지 않음|
|PRV-04|적합성 시험 게이트|소유권·세대, 중단, 결과 전달·재전송, 원본 비보관, 비밀값 비노출, 미보고 사용량 null, 문맥 전달 기록을 공통 시험으로 검증. 통과 전에는 배정 후보가 아님|
|PRV-05|모델 후보·선택 연계|CR-003 정책(후보→검증→사용→철회)에 새 제공자 모델 포함. 작업군별 근거 없이 승격 안 함. 공개 벤치마크는 후보 신호로만 표시. 2026-10-03 사용자 추가 요구: Claude Routine 마스터 모델(현재 Opus 5.5)도 근거에 따라 최신화한다. INNO 서비스는 Routine 설정 권한이 없으므로 근거와 함께 교체를 추천하고, 승인 시 Claude Code 세션(RemoteTrigger)이 갱신한다|
|PRV-06|관리 화면|제공자 추가·연결 상태·capability·배정 근거·비활성화를 데스크톱/모바일에서 제공|
|PLG-01|플러그인 등록부|Agent Skills(SKILL.md)·MCP 서버 형식 우선. 출처·버전·내용 해시 고정, 제공자별 호환성 기록|
|PLG-02|신뢰·권한|허용 출처(공식·검증 카탈로그)만 후보. 설치 전 검토/스캔 보고와 사용자 승인. 스크립트·네트워크·파일 권한을 선언하고 최소 권한. 원본·비밀값 접근 금지. 해시 불일치 시 즉시 비활성|
|PLG-03|작업별 적용 결정|마스터가 작업 분야·완료 기준에 맞는 조합을 고르고 이유 기록. 같은 기능 중복 적용 금지. 실행 기록에 적용 내역 저장|
|PLG-04|효과 측정·승격·도태|정상 작업 관측(독립 품질 검토, 토큰·시간)과 비AI 회귀를 기본으로 하고, 추가 비교는 사용자 설정 예산 안에서만. 명확히 우수한 대체가 검증되면 기존 플러그인을 새 작업에서 자동 제외하고 삭제를 추천. 실제 삭제는 사용자 확인 후, 근거 기록 보존. 회귀 시 이전 조합으로 복구|
|PLG-05|추천|허용 카탈로그를 제한된 주기(하루 1회)로 조회해 후보와 추천 사유·위험·근거를 제시. 자동 설치 없음|
|PLG-06|제외 범위|제출물의 AI 작성 은폐(탐지 회피) 목적 플러그인 제외. 미검증 효과를 성과로 표시하지 않음|

## 5. 단계 WBS (각 단계: 구현자/별도 검증자 → 검증 → PROGRESS 기록)
1. S0 승인과 CR-004 결정.
2. S1 제공자 레지스트리 추상화: 기존 두 제공자를 계약으로 이전, 적합성 시험 스위트, 저장 구조 마이그레이션 검증(동작 변화 없음).
3. S2 새 제공자 시범 1개: 사용자가 실제 구독 중인 서비스의 공식 CLI로, 이용약관상 자동 실행 허용 여부를 먼저 확인. 실구독 최소 시험은 실행 전 확인.
4. S3 플러그인 등록부·권한·적용 기록: 1차는 공식 카탈로그의 SKILL.md만, 스크립트 없는 스킬부터.
5. S4 효과 관측·도태·추천 화면.
6. S5 릴리스와 요구 재감사.

## 6. 위험·가정·비범위
- 새 언어/빌드 도구/런타임 추가: 아니오(기존 JS/Node/Worker/D1). 제공자 CLI 자체는 사용자가 설치하는 외부 프로그램이며 INNO가 대신 설치·로그인하지 않는다.
- 저장 구조 변경(제공자 값 일반화)은 마이그레이션·롤백 검증을 포함한다.
- 제공자 이용약관이 자동 실행을 제한할 수 있다. 제한되면 해당 제공자는 지원하지 않는다.
- 모든 작업·시점에서 최선의 모델·플러그인을 보장하지 않는다. 근거가 있는 작업군과 범위만 표시한다.
- 비범위: 유료 API 전환, 비공식 우회 로그인, 검증 없는 자동 설치, 원본 영구 업로드.
