# 실행 토큰 사용량과 문맥 전달 기록

2026-10-03 기준 코드(`public/core/execution-usage.mjs`, `public/core/context-delivery.mjs`)와 맞춘 설명이다. 보고되지 않은 값은 추정하지 않으며 0으로 표시하지 않는다.

## 무엇을 저장하나
- **실행별 사용량 이력**: 각 작업 checkpoint의 `usageHistory`에 실행마다 한 줄씩 남긴다(작업당 최근 100건). 실행 ID·세대, 제공자, 단계(마스터/하위/검토), 전환(완료·실패·위임·인계·재시도·결정 대기 등)과 입력·출력 토큰, 보고된 경우 캐시 입력 토큰을 담는다. 같은 실행의 재전송은 중복 저장하지 않는다.
- **최근 완료 실행 사용량**: checkpoint의 `usage`는 마지막 완료 실행의 보고값이다.
- **문맥 전달 기록**(2026-10-03 추가, 운영 반영 전): checkpoint의 `contextDelivery`에 그 실행이 받은 문맥의 전달 방식(전문/예산 초과 전문/선택/차단)과 UTF-8 바이트 수, 생략 원문 수, 전체 프롬프트·첨부 발췌 바이트를 남긴다. 토큰 값은 이 기록에서 항상 비워 둔다. 새 실행을 시작하면 이전 기록은 지워진다. 이 기록은 "보낸 문맥"이며 모델이 처리했다는 뜻이 아니다. Claude Routine이 인증·사용 한도로 확정 거절한 경우에도 보낸 본문의 기록을 남긴다(2026-10-03, Codex 실행 오류와 같은 기준). 응답이 불확실해 확인을 기다리는 실행은 전달 여부를 알 수 없으므로 기록하지 않는다.

## 값의 출처와 한계
- Codex: 데스크톱 실행기가 CLI가 보고한 입력·출력(및 캐시) 카운터를 결과와 함께 보낸다. 실행 중 실시간 수치, 강제 중단 전 미보고량, 하위 에이전트까지 합친 독립 검증은 아니다.
- Claude: Routine이 완료 도구 호출에 사용량을 넣은 경우에만 저장한다. 도구 설명은 실제 실행기 보고값만 넣고 모르면 생략하라고 요구하지만, 그 값의 정확성을 INNO가 독립적으로 검증하지는 않는다. 넣지 않으면 확인 불가로 남는다.
- 캐시 입력은 전체 입력보다 클 수 없으며, 그렇지 않은 값은 버린다. 음수·무한대·안전 정수 범위 밖 값과 임의 필드는 저장하지 않는다.
- 계정 전체 소비량, 요금, 구독 잔여량을 뜻하지 않는다. 구독 사용량을 API 가격으로 환산하지 않는다. 한도와 초기화 시각은 제공자 화면에서 확인한다.

## 화면
- 사용량 화면은 모든 작업에서 최근 50개 실행과 제공자별 합계(보고된 값만)를 보여 준다. 단계·전환·경과 시간·요청 모델을 함께 표시하며, 요청 모델은 실제 서빙 모델 확인을 뜻하지 않는다.
- 작업 상세의 재개 지점 카드에 마지막 실행의 문맥 전달 기록을 한 줄로 표시한다.
- 과거 누락 수치를 소급 생성하지 않는다. 기록 가져오기 형식에 따라 부가 관측값이 유지되지 않을 수 있다.
