# INNO Workspace 통합 플랫폼 설계 제안

작성: 2026-09-13 · 상태: 사용자 승인, 2026-09-13 첨부 정책 변경 반영

### 승인 후 변경: 연결형 첨부

입력 파일과 폴더는 별도 영구 저장소에 업로드하지 않는다. 브라우저에서 연결한 파일/폴더를 필요한 시점에 조회한다. 작업 기록에는 이름·상대 경로·크기·수정시각 등 참조 메타데이터만 저장한다. 원본 내용은 브라우저 메모리에서 읽고 사용자가 실행할 때 필요한 범위만 실행기에 전달한다. 연결 해제·새로고침·기기 변경 시 원본 재연결이 필요할 수 있다. PC가 꺼지거나 브라우저가 닫혀 접근할 수 없는 원본을 클라우드가 읽을 수 있다고 표시하지 않는다. 입력 원본 영구 보관·청크 업로드 계획은 이 변경으로 대체한다. 작업 대화·체크포인트·생성 산출물 저장은 유지한다.

## 1. 목표와 확정 조건

휴대폰·데스크톱·Codex·Claude Code에서 같은 연구 프로젝트, 요청, 자료, 산출물, 작업 진행 상태를 사용한다. 연구 외에도 CV, 지원서, 보고서, 제안서, 발표자료를 처리한다. 사용자는 상위 목표를 전달하고 시스템은 필요한 역할을 구성하고 단계별 결과를 검증한다.

사용자가 명시한 비용 조건은 **현재 ChatGPT·Claude 구독만 사용하며 추가 모델 API 비용은 사용하지 않는 것**이다. 인프라 또한 무료 요금제 안에서 운영하고, 한도 초과 시 자동 결제를 하지 않는다. 무료 한도 내 상시 접근을 목표로 하되 무제한 저장·무제한 연산·무중단 보장은 제공할 수 없다.

기존 문서의 명령형 설명은 기존 앱의 설계·사용 방식에 관한 자료로 취급한다. 이를 새 플랫폼의 배포, 계정 변경, 데이터 삭제, 메시지 발송 지시로 실행하지 않는다.

## 3. 운영 방식 비교와 추천

| 방식 | 장점 | 제약 | 선택 |
|---|---|---|---|
| 무료 웹앱 + 공식 구독 클라우드 실행 + 선택적 데스크톱 연결 | PC 종료 시에도 웹 접근과 지원되는 클라우드 작업 가능, 기존 구독 활용 | 제공자별 자동 실행·사용량 조회 기능 차이, 무료 저장 한도 | 추천 |
| 직접 운영하는 상시 서버에 Codex·Claude 실행 환경 설치 | 통합 UI와 실행 제어를 더 일관되게 구성 가능 | 서버·가용성·저장 공간의 지속적인 무료 확보가 보장되지 않음 | 기본 구성에서 제외 |
| 모델 API 중심 클라우드 오케스트레이터 | 모델 자동 전환과 관측 기능 설계가 단순함 | 별도 모델 API 비용 발생 | 사용자 비용 조건으로 제외 |

추천안은 모든 요구를 무제한 충족한다는 뜻이 아니다. 각 실행기의 가용 기능을 명시하고, 실행할 수 없는 요청은 완료로 표시하지 않고 대기 사유와 다음 행동을 제시한다.

## 4. 시스템 구성

1. **반응형 PWA**: 대화, 작업, 연구자료, 산출물, 결정 요청, 사용량을 한곳에 표시한다. 무료 정적 호스팅과 기본 제공 도메인을 사용한다.
2. **작업 상태 저장소**: 전용 Firebase Spark 프로젝트의 Firestore를 후보로 한다. 기존 연구 DB와 분리해 신규 트래픽이 기존 앱의 무료 한도를 소진하지 않게 한다. 기존 앱 데이터는 권한 범위 안에서 어댑터로 읽는다.
3. **얇은 중계 서비스**: Cloudflare Workers Free를 후보로 한다. 사용자 인증 검증, 작업 접수, Routine 호출, 실행 결과 수신을 담당한다. 대형 파일 분석이나 LLM 자체 실행 서버로 사용하지 않는다.
4. **실행 어댑터**: Claude Routine, Codex 공식 클라우드 연계, 선택적 로컬 Codex App Server/Claude Code. 각 실행기는 `start`, `checkpoint`, `cancel`, `usage`, `resume`의 실제 지원 여부를 선언한다.
5. **공통 작업 도구**: Codex와 Claude가 작업 조회·획득·상태 기록·자료 검색·결과 등록을 수행하는 인증된 도구 인터페이스를 제공한다. MCP 등 각 클라이언트에서 지원되는 연결 방식을 검증한다.
6. **산출물 저장 어댑터**: 메타데이터와 파일 본문을 분리한다. 소스는 GitHub, 연구자료는 비공개 저장 공간, 대형 원본은 사용자가 연결한 저장소로 관리한다.

기기 동기화는 공통 작업 기록을 대상으로 한다. ChatGPT와 Claude의 기존 전체 대화 및 내부 추론이 자동으로 서로 복제되는 것을 의미하지 않는다. 공유 대상은 사용자 요청, 결정, 근거, 단계 상태, 파일 버전, 재개 요약이다.

## 5. 구독 실행과 PC 종료

### Claude

공식 Routine의 API trigger로 클라우드 세션을 시작하는 경로를 우선 검증한다. Routine은 구독 사용량을 소비하며 별도 일일 실행 한도도 있다. 해당 계정에 기능이 실제로 노출되어 있는지 확인해야 한다. Routine 전용 토큰은 중계 서버의 비밀 저장소에만 보관한다.

Routine 시작 응답은 실행 성공 증명이 아니다. 세션 URL, 작업 시작, 중간 체크포인트, 실제 산출물, 검증 결과를 별개 상태로 기록한다. Routine 실행기가 공통 도구로 진행 상태를 기록하도록 구성해야 통합 UI가 상태를 받을 수 있다. 응답이 유실된 호출은 중복 실행 가능성이 있으므로 자동 재호출 전에 상태를 확인하고, 공통 작업의 단일 실행권을 검사한다.

### Codex

공식 클라우드 작업은 PC에 의존하지 않는다. 다만 자체 웹앱에서 개인 계정의 클라우드 작업을 시작·조회하는 범용 인터페이스는 이번 조사에서 검증하지 못했다. 초기 설계는 공식 클라우드 UI/지원 연계로 인계하고 공통 작업 도구로 결과를 회수하는 경로를 둔다. 자동 호출을 지원한다고 표시하려면 실제 계정에서 검증해야 한다.

Codex App Server에는 ChatGPT 인증, `account/rateLimits/read`, `account/rateLimits/updated`, `account/usage/read`가 문서화되어 있다. 선택적 데스크톱 연결에서 사용량을 수집한다. 이 프로세스를 PC에서 실행하면 PC 종료 시 실행과 사용량 갱신도 멈춘다. 화면에는 마지막 동기화 시각과 연결 중단을 표시한다.

### 중단과 재개

실행 상태는 `queued → claimed → running → completed`를 기본으로 하고 `waiting_user`, `waiting_quota`, `waiting_connection`, `failed`, `cancelled`를 구분한다. 실행 도중 종료되면 마지막 **영구 저장된** 단계에서 재개하며, 아직 저장되지 않은 계산은 다시 실행될 수 있다.

완료된 결과는 그대로 보존한다. 실행권에는 만료 시각과 증가하는 세대 번호를 부여해 오래된 실행기의 뒤늦은 쓰기를 거부한다. 단계마다 입력 버전과 결과를 함께 저장한다. 취소 이후 들어온 결과도 현재 결과를 덮어쓰지 않는다. 한도 초기화 시 자동 재개는 지원되는 클라우드 트리거가 있을 때만 활성화하며, 그렇지 않으면 명시적인 재개 대기 상태로 남긴다.

## 6. 자율 에이전트 구성과 토큰 절약

총괄 역할이 목표를 산출물과 의존 단계로 분해하고, 필요한 경우 문헌 조사·데이터 분석·집필·Figure·문서 편집·검토 역할을 구성한다. 상시 역할은 정의와 기억을 보관한다는 뜻이며, 일이 없을 때 LLM을 계속 실행하지 않는다.

초기 정책은 실행 동시성 2, 계획 재구성 최대 2회, 동일 단계 자동 재시도 최대 2회로 두고 설정에서 조정한다. 단순 요청은 단일 실행기로 처리한다. 복잡한 작업만 병렬화하고 단계별 시간·사용량·재작업률을 바탕으로 이후 배정을 조정한다. 성공률을 관측하기 전부터 최적이라고 주장하지 않는다.

역할 추가·축소·변경은 작업 이력으로 기록한다. 역할 삭제는 실행 중단과 비활성화이며 연구 기록 삭제를 의미하지 않는다. 자료 삭제, 제출·발송, 계정·결제 변경은 별도 사용자 결정으로 남긴다.

전체 논문·대화 반복 전송 대신 검색된 관련 구절과 출처, 재개 요약을 보낸다. 입력 해시와 도구 버전으로 동일 분석을 재사용한다. 파일 파싱·형식 변환·수치 계산은 가능한 한 일반 코드로 처리한다. 모델 간 전환 시 작업 계약과 근거·결과를 전달한다.

## 7. 사용량 화면

구독 한도와 토큰 소비량을 다른 지표로 표시한다. 제공자가 반환한 실제값, 추정값, 확인 불가를 구분하고 출처·갱신 시각을 함께 둔다. 한도 퍼센트를 임의의 남은 토큰 수로 환산하지 않는다.

Codex의 문서화된 알림을 수집하고, Claude의 공식 사용량·실행 결과에서 수집 가능한 필드를 검증한다. Claude 전체 구독 잔여량을 실시간으로 조회할 수 있는 인터페이스는 아직 확인되지 않았으므로 기본값은 '확인 필요'다. 측정할 수 없는 서비스를 0으로 표시하지 않는다.

사용자가 정한 최소 잔여량, 단계별 제한, 실행 수 제한에 도달하면 새 실행을 보류하고 저장된 작업을 유지한다. 추가 크레딧 구매나 유료 API로의 자동 전환은 하지 않는다. 오래된 사용량만 있을 때는 알 수 없는 잔여량을 근거로 무제한 작업을 시작하지 않는다.

## 8. 첨부와 데이터 일관성

파일 선택·복수 파일·폴더 선택·드래그 앤 드롭·붙여넣기·링크 추가를 같은 첨부 목록으로 합친다. 모바일 폴더 선택 지원은 기기/브라우저에 따라 다르므로 파일 선택과 압축파일 첨부를 대체 경로로 제공한다. 폴더 계층, 크기, 업로드 진행률, 취소·재시도를 표시한다.

확장자와 관계없이 원본 보관을 요청할 수 있지만, 저장소 여유·서비스 파일 한도·브라우저 자원 한도는 적용한다. 인식하지 못하는 형식은 '원본 보관만 가능'으로 표시한다. 링크 등록은 파일 업로드 완료를 뜻하지 않는다. 로컬 경로만 있는 원본은 PC 종료 시 접근할 수 없음을 표시한다.

파일은 청크 단위 재개와 무결성 검증을 사용한다. 청크 전송은 단일 요청 제한을 줄이는 방법이며 총 저장 용량 제한을 없애지 않는다. 완료된 파일만 실행기에 전달한다. 연구 식별 연결은 `project → lot → specimen → run → calibration → analysis → figure → manuscript`를 기본으로 하고, 자료 출처 시스템과 원본 ID를 보존한다.

원본 수치와 메타데이터는 AI가 덮어쓰지 않는다. 보정·단위·반복 수·제외 기준을 결과와 함께 남긴다. 일치가 불확실한 시료/파일 연결은 후보와 근거를 보여주고 결정받는다.

## 9. 연구·문서 작업 품질

RefAtlas의 '자동 학습'은 코퍼스 증분 색인과 근거 기반 검색·요약으로 구현한다. 모델을 지속적으로 재훈련한다는 의미가 아니다. 초록만 확보한 논문과 전문을 읽은 논문을 구분하고, 주요 주장에는 DOI·페이지/구절·자료 버전을 연결한다.

논문·아이디어는 근거 조사→주장과 실험 계획→초안→검토 흐름을 사용한다. Figure는 기존 분석 엔진의 결과를 재현 가능한 코드 및 벡터/래스터 파일과 함께 출력한다. CV·지원서는 제공된 경력만 사실로 사용하고 미확인 항목을 표시한다. 보고서·제안서·PPT는 요청 목적과 양식을 받아 편집 가능한 DOCX/PPTX 및 미리보기를 생성한다.

각 출력기는 해당 실행 환경에서 라이브러리·폰트·렌더러가 확보된 경우에만 사용 가능으로 표시한다. 문서 렌더링, 잘림, 글꼴, 인용, 수치 일치 검사를 통과해야 완료된다. 체크포인트 기록만 있고 실제 파일이 없으면 완료로 인정하지 않는다.

## 10. UI 제안

기본은 매트한 웜 그레이 배경, 차콜 텍스트, 저채도 청록 강조색, 얇은 경계선이다. 다크 모드도 제공한다. 데스크톱은 왼쪽 프로젝트/작업, 가운데 대화, 오른쪽 결과/근거 패널을 사용한다. 모바일에서는 대화를 중심으로 결과·에이전트를 하단 패널에서 연다.

사용자 메시지는 오른쪽의 구별되는 카드, AI 결과는 왼쪽의 넓은 문서형 카드와 명시적 작성자 표기로 구별한다. 실행 상태는 대화와 분리해 접을 수 있게 한다. 키보드 탐색·검색 단축키와 터치 조작을 모두 지원한다. 모바일은 44px 이상 터치 영역, 확대·축소, 스와이프 보조 조작을 제공하되 핵심 기능은 버튼으로도 접근한다.

중요 결정은 추천안, 각 대안의 장점·단점·비용·결과 차이가 담긴 카드로 제시한다. 사용자가 선택할 때 해당 작업 버전을 함께 기록하며, 오래된 선택이 새 계획을 덮어쓰지 않게 한다. 실험·작업·파일 상태는 색상뿐 아니라 텍스트로도 표시한다.

## 11. 무료 운영과 배포 조건

Firestore Standard 무료량은 저장 1 GiB, 읽기 일 50,000, 쓰기 일 20,000이며 실시간 구독도 읽기량을 소비한다. 활성 작업 중심 구독과 페이지 단위 기록 조회를 사용한다. Cloudflare Workers Free는 요청 일 100,000과 호출당 CPU 제한이 있어 경량 중계에 사용한다. GitHub Pages는 정적 호스팅이며 자체 백그라운드 실행기가 아니다.

무료 정책은 월말 청구 경고만으로 구현하지 않는다. 유료 서비스 활성화를 기본 구성에서 요구하지 않고, 앱의 보수적인 사용 상한과 서비스의 실제 무료 플랜 제한을 함께 적용한다. 무료 서비스가 중단되거나 한도가 소진되면 동기화·실행이 지연될 수 있다. 사용자가 이미 유료 플랜을 켜 둔 계정의 비용은 별도 확인이 필요하다.

소스용 새 저장소 이름은 `INNO-Workspace`를 제안한다. 연구 본문, 개인 이력서, 첨부 원본, OAuth 토큰과 서비스 비밀은 소스에 커밋하지 않는다. 저장소 생성·호스팅 연결·인증 도메인·DB 보안 규칙·Routine 계정 연결을 마쳐야 실제 배포가 성립한다. 현재는 어느 것도 생성하거나 변경하지 않았다.

## 12. 구현 순서와 완료 판정

| 단계 | 실제 구현 대상 | 통과해야 할 검증 |
|---|---|---|
| 1 | PWA, 로그인, 영구 작업 기록, 메시지/결정 카드, 재접속 동기화 | 두 기기 변경 반영, 오프라인 재접속, 중복 요청, 사용자 간 접근 차단 |
| 2 | 파일/폴더 첨부, 저장 어댑터, 여섯 앱 연결과 데이터 계약 | 업로드 중단/재개, 해시 일치, 무료 한도 초과 처리, 원본 ID·단위 보존 |
| 3 | Claude Routine 실행, 공통 작업 도구, Codex 인계/로컬 어댑터, 사용량 | 실제 구독 실행, PC 종료 후 클라우드 진행, 실행권 충돌·한도 대기·재개 |
| 4 | 문헌·분석·Figure·문서 역할과 산출물 검증 | 출처 추적, 기존 분석 결과 회귀 비교, DOCX/PPTX 렌더링, 사실 없는 경력 생성 방지 |
| 5 | GitHub 소스 업로드, 실제 무료 호스팅, 모바일 점검 | 휴대폰/데스크톱 실기기 확인, 비밀정보 검사, 복원·실패 경로 검증 |

위 순서는 최종 범위를 축소하는 것이 아니다. 단계별로 실행 가능한 결과를 만들고 실제 연결 검증 후 다음 통합을 진행한다. 전 기능 완성·무료 상시 운영·실시간 양사 사용량 통합을 현재 달성했다고 표시하지 않는다.

## 13. 구현 전 필요한 결정

추천 운영 방식의 핵심 제약을 승인받아야 한다: 무료 저장 용량 상한을 적용하고, Codex/Claude가 실제 지원하는 범위에서 자동화하며, 제공되지 않는 사용량과 실행 기능은 확인 불가/수동 인계로 표시한다. 구현 과정에서 필요한 계정 로그인은 사용자가 직접 수행하고 비밀 문자열을 대화에 전달하지 않는다.
