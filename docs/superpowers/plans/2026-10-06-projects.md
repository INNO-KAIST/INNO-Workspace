# Projects and renaming (CR-008) Implementation Plan

**Goal:** Group tasks into projects like ChatGPT/Claude projects: create a project and start tasks in it, move existing tasks in and out, rename projects and tasks, and give a project shared instructions that every execution of its tasks receives.

**User decisions (2026-10-06):** start right after PRV-06; projects carry grouping plus shared instructions (no shared files: originals are never uploaded); deleting a project keeps its tasks (they show as "프로젝트 없음").

**Architecture:** Projects are small JSON rows in D1 `metadata` (`project:<id>`), so no migration is needed. A task carries an optional `projectId`; delegation children follow their parent's project. Project writes bump the workspace revision, and every non-`unchanged` state answer carries the whole project list. Deleting a project removes only its row: tasks that still name it read as "no project" everywhere, so no task record is rewritten. Instructions travel with the execution (desktop claim `project`, Claude Routine prompt) as an inline block outside the 96 KB context budget, bounded by the 8,000-character cap at write time.

**Scope:** cloud mode (Worker, Pages, desktop proxy). Task rename works in every mode through the shared actions; the local Node server and browser-only storage do not offer projects (the UI shows projects only with `capabilities.projects`).

## Global constraints
- Subscription runners only; no paid API. Originals are never uploaded (no project files).
- Project name 1-80 characters, instructions 0-8,000 characters, at most 100 projects; task title 1-120 characters.
- Rename and move are state changes: allowed on finished tasks and on tasks above the growth limit; refused on delegation children (they follow the parent).
- Old pages, the old connector and the local modes keep working (they ignore `projects`/`projectId`/`claim.project`).
