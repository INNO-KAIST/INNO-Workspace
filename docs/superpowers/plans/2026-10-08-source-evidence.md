# 근거 추적(차별화 강화안 ②) 설계

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 원본 자료로 만든 결과에서 핵심 주장마다 원본 파일의 위치와 짧은 원문 인용을 붙이고, 인용이 실제 원문에 있는지 이 PC에서 확인해 "원문 확인됨 / 원문에서 찾지 못함 / 근거 없음"을 보인다. docs/DIFFERENTIATION-PROPOSAL.md ②.

**사용자 결정(2026-10-07):** 권장 순서 승인(① 다음 ②).

## 원칙
- 원본 비보관: 원본 파일·전문은 클라우드에 올리지 않는다. 위치(쪽·행·절 표기), 200자 이내 인용, 확인 결과만 남긴다(지금도 답에 근거 발췌를 쓰는 범위와 같다).
- 확인은 실행기가 원본 텍스트를 가진 이 PC에서만 한다(실행 중 받은 자료와 대조). 위치 표기 자체는 확인하지 않는다(문서마다 쪽 번호 체계가 달라서). 인용이 원문에 없으면 "원문에서 찾지 못함".
- 모델이 근거를 내지 않으면 기록하지 않는다(기존 결과는 그대로). 근거가 없는 주장은 "근거 없음"으로 보인다. 효과를 주장하지 않는다.

## 범위
- 대상: 원본 텍스트 자료를 받은 데스크톱 **최상위** 실행(Codex, Claude Code 실행기 공통 프롬프트). 이미지만 있는 자료·클라우드 Routine·원본 없는 작업·하위/검토 실행(경로 조건 계약으로 프롬프트 고정)·로컬 전용 서버 모드(server/index.mjs)는 대상 아님. 원본이 없는 프롬프트는 한 글자도 바뀌지 않는다.
- 프롬프트: 원본이 있으면 결과 JSON에 `claims:[{text, sources:[{source:<원본 번호>, locator, quote}]}]`(핵심 주장 최대 30개)를 요청. 지어낸 위치·인용 금지, 근거 없으면 `sources: []`.
- 실행기: `claims`를 원본 이름(우선) 또는 번호(숫자 글자도 허용)에 맞춰 정리하고 인용을 원문과 대조(공백 정규화·대소문자 무시, 8자 미만 인용은 확인 안 됨). 결과 `sourceEvidence = {version:1, claims:[{text, sources:[{name, locator, quote, found}]}]}`.
- 연결기 → Worker: 데스크톱 완료에만 받는다. 이름은 작업의 원본 목록 안에서만, 길이 상한(주장 30·주장 500자·근거 5·위치 100자·인용 200자·기록 전체 32,000바이트). 연결기는 결과 전체가 전송 한도(700KB)에 가까우면(690KB 초과) 기록만 빼고 결과를 보낸다. 잘못된 기록은 버리고 결과는 항상 저장. 저장: `checkpoint.sourceEvidence`(실행 id 포함). 모든 완료가 이전 기록을 지우므로 기록은 항상 최신 결과에 대한 것.
- 화면: 작업 상세에 "근거 추적" 접이식 구역 — 요약(주장·원문 확인·찾지 못함·근거 없음 수)과 주장별 근거.

## 시험
- 공통: 원본 번호·이름 대응, 인용 확인(있음·없음·공백 차이), 근거 없는 주장, 상한, 잘못된 항목 무시, Worker 검증(원본 목록 밖 이름 거절).
- 실행기: 원본이 있을 때 프롬프트 지시, 결과에 sourceEvidence, 원본이 없으면 없음.
- Worker: 데스크톱 완료에서 저장, 클라우드 완료는 받지 않음.
- 화면: 요약·줄 문구.
