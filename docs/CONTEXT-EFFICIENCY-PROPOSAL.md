# CR-005: 장기 작업 문맥·토큰 최적화 제안
작성: 2026-10-01. 상태: 승인됨 — 2026-10-01 사용자 “토큰 최적화 관련 초안 승인할게”.

## 목표와 확인된 문제
사용자 요구는 모든 작업과 Codex/Claude 양쪽에서 문맥 비용을 줄이면서 목표·제약·결정·미완료 작업·근거를 재개 시 이어받는 것이다.
현재 server/runners.mjs taskPrompt와 worker/index.mjs routineText는 원래 요청, 최근 20개 메시지(각 앞 8000자, 합계 뒤 80000자), checkpoint 앞 8000자를 조립한다. 오래된 결정과 긴 메시지 뒷부분이 조용히 빠질 수 있고 후속 대화에서는 원래 요청이 중복될 수 있다.

## 제안 방식
- 공급자 공통 문맥 패킷: 현재 목표, 명시 제약, 승인된 결정, 완료/미완료 항목, 진행 중 실행, 근거 참조와 최신 변경을 구조화한다. 마스터/자식/검토/인계에 필요한 범위를 각각 선택한다.
- 작업 이력은 필요할 때 조회한다. 패킷에 포함·생략된 메시지 식별자, 해시, 버전, 재조회 경로를 남긴다. 오래된 요약을 다시 요약하는 것만으로 상태를 이어가지 않는다.
- 동일 내용은 한 번만 전달하고 안정된 지침 순서를 유지한다. 작업·자료·요구사항이 변경되면 관련 패킷을 무효화한다. 계정/작업/에이전트 범위를 넘는 재사용은 금지한다.
- 압축은 안전한 단계 경계에서 한다. 실행 중 도구 결과, 미전달 산출물, 미결정 질문, 승인 범위를 유지한다. 필수 상태가 예산을 넘으면 조용히 자르지 않고 필요한 조회/분할을 먼저 수행하며 해결 불가능하면 원인을 표시한다.
- 토큰 추정, 전송 바이트, 관측 input/output/cached token 및 요약 비용을 분리한다. 캐시 적중이나 구독 잔여량을 추측하여 절감 성과로 표시하지 않는다.

## 요구사항과 완료 기준
| ID | 요구사항 | 검증 기준 |
|---|---|---|
| CTX-01 | 두 실행 경로의 공유 문맥 조립 | 같은 작업 상태가 동일한 필수 사실/참조를 제공; 역할 밖 자료가 자식에게 전달되지 않음 |
| CTX-02 | 중복 제거와 요청 예산 | 반복 대화의 불필요한 원문 재전송 감소를 고정 fixture로 측정; 실제 tokenizer 없으면 추정으로 표시; 중요 내용을 길이만으로 삭제하지 않음 |
| CTX-03 | 누락 탐지와 선택 조회 | 20개 이전 결정·긴 메시지 끝부분·변경된 지시·파일 변경·재시작 사례에서 누락을 감지하고 근거를 다시 조회; 조회 불가 표시 |
| CTX-04 | 검증 가능한 재개 상태 | 요약/상태의 원본 범위·버전·해시와 충돌을 검증; 손상/오래된 요약을 권위 있는 사실로 쓰지 않음; 체크포인트 교체 원자성 |
| CTX-05 | 비용 및 캐시 관측 | 미보고 값 null 유지, 입력/출력/캐시/압축 비용 분리, 성과는 동일 작업 비교에만 표시 |
| CTX-06 | 누적과 반복 제한 | 패킷 재사용·백오프·정리 상한, 활성 작업이 참조하는 근거 보호, 추가 AI 압축/평가 기본 0회; 설정된 예산 없이는 별도 AI 실행 안 함 |

## 순차 구현 계획
1. 현재 누락/중복 사례를 재현하고 공통 패킷·길이/누락 manifest·안정된 조립을 구현한다. 추가 AI 없이 검증한다.
2. 명시 상태와 변경 이력, 범위 제한 원문 조회, 제공자 전환/재시작을 연결한다. 필수 과거 지시를 최근 대화만으로 대체하지 않는다.
3. 필요 시 정상 작업의 결과와 함께 요약을 갱신하고 출처/범위/누락을 검증한다. 독립 압축 실행은 기본 비활성, 비용·효과와 사용자 예산을 확인한 경우에만 사용한다.
4. 토큰·바이트·캐시 관측 UI, 장기 대화·여러 역할·장애·재연결 회귀 및 실제 지원 구독 경로 통합 검증 후 배포한다.
각 단계는 구현자/별도 검증자로 나누고 기존 승인 Node·Wrangler 검증 명령을 사용한다.

## 위험·가정
- 이번 작업으로 새 언어/빌드 도구/런타임이 추가되는가? 아니오. 기존 JS/Node/Worker/D1을 사용한다. 저장 구조 변경은 적용 전 구체화하고 마이그레이션 검증한다.
- 의미상 완전 무손실 압축은 보장하지 않는다. 필수 상태의 명시 보존, 누락 탐지, 원본 재조회와 검증으로 위험을 줄인다.
- 첨부 원문을 별도 영구 저장하지 않는다. 원본이 연결되지 않으면 재연결이 필요하다. 작업 대화/결정/생성 산출물과 원본 첨부를 구분한다.
- 현재 데스크톱 앱 대화의 내부 압축 시점, 공급자 캐시 정책, 구독 계산은 INNO가 직접 제어한다고 주장하지 않는다.
- 유료 API/벡터DB/추가 서비스 도입 없음. API 전용 압축 기능이 구독 CLI/Routine에서 사용 가능하다고 가정하지 않는다.
