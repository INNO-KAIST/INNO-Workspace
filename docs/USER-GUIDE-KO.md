## 2. 반드시 구분할 세 가지 모드

| 모드 | 기록 위치 | 현재 AI 실행 | 다른 기기 공유 |
|---|---|---|---|
| 이 기기 보관 | 해당 브라우저 IndexedDB | 불가 | 자동 공유 안 됨 |
| 로컬 서버에 연결 | 이 PC의 SQLite | 현재 ChatGPT 구독 Codex | 클라우드 DB와 자동 공유 안 됨 |
| 클라우드 서버에 연결 | Cloudflare D1 | Routine 미연결로 현재 불가 | 같은 서버·토큰 연결 시 가능 |

**클라우드 작업을 PC의 Codex가 자동 가져오는 연결 프로그램은 아직 구현되어 있지 않습니다.** 클라우드와 로컬은 같은 디자인을 쓰지만 기록 저장소가 다릅니다. 설정만 바꿔 전체 요구가 완성되는 상태는 아닙니다.

현재 클라우드 제공 범위는 상시 접속·작업 기록·인증·상태 공유입니다. PC 종료 중 AI 계산, ChatGPT/Claude 기존 대화의 자동 합치기, 실험 DB 완전 통합은 남은 개발·연동 항목입니다.

## 3. PC에서 클라우드 작업실 연결

1. `.inno/CLOUD-ACCESS.md`를 엽니다.
2. 그 안의 **개인 클라우드 작업실 열기** 링크를 누릅니다.
3. 주소에 포함된 개인 토큰을 앱이 받아 세션에 보관한 뒤 주소에서 제거합니다.
4. 상단에 **동기화**, 설정 영역에 **서버 연결됨**이 보이는지 확인합니다.
5. 시험 작업을 하나 작성합니다. 기록 버튼은 작업을 저장하며 AI 실행을 뜻하지 않습니다.

일반 주소로 들어가 **이 기기 보관**이 보이면 서버 연결이 안 된 상태입니다. 우측 **연결 설정** 또는 좌측 아래 **개인 작업실 ⚙**에서 다음을 입력합니다.

- 서버 주소: `https://inno-workspace-api.innokaist.workers.dev`
- 작업실 접근 토큰: `.inno/cloud-access-token.txt` 내용
- **연결 확인** 클릭

이 토큰은 ChatGPT/Claude API 키가 아닙니다. GitHub 비밀번호나 Cloudflare 로그인 비밀번호도 넣지 않습니다. 토큰이 포함된 링크를 다른 사람에게 공유하지 마세요.

토큰은 탭의 세션에만 저장됩니다. 새 브라우저·새 탭·브라우저 재시작 후 다시 연결을 요구할 수 있습니다. 단순히 주소를 즐겨찾기했다고 인증까지 영구 유지되는 것은 아닙니다.

## 4. 휴대폰 연결

1. 휴대폰 브라우저로 클라우드 주소를 엽니다.
2. **작업 상세 열기 → 연결 설정**으로 이동합니다.
3. PC와 같은 서버 주소와 작업실 접근 토큰을 입력합니다. 토큰은 본인만 접근하는 비밀번호 관리자 등으로 옮깁니다.
4. PC에서 만든 시험 작업이 휴대폰에 보이는지 확인합니다.
5. 휴대폰에서 요청을 추가하고 PC의 같은 작업에서 확인합니다. 활성 탭은 약 5초마다 조회합니다.

기록만 공유하며 PC의 E: 드라이브 파일을 휴대폰에서 자동 읽지는 않습니다. 모바일 폴더 선택은 브라우저 지원 여부에 따라 제한되므로 그 경우 필요한 파일을 개별 선택합니다. 가로 스와이프로 펼쳐진 좌측 메뉴·우측 상세 패널을 닫을 수 있습니다.

현재 이 PC의 Codex 인증은 `Logged in using ChatGPT`로 확인했습니다. 개발 검증에서 실제 응답과 SVG 생성까지 통과했습니다.

터미널 창과 PC가 켜져 있어야 실행이 계속됩니다. 브라우저만 닫아도 서버가 살아 있으면 계산은 계속할 수 있습니다. PC를 끄거나 서버 창을 닫으면 로컬 계산이 멈춥니다. 서버 재시작 시 기본 접근 토큰은 새로 생성되므로 새 터미널 주소로 다시 접속합니다. 작업 DB는 유지됩니다.

### 실행기 연결이 안 될 때

Codex 앱의 터미널에서 프로젝트 폴더로 이동한 뒤 확인합니다.

```powershell
Set-Location -LiteralPath 'E:\Develop\INNO Workspace'
codex login status
node server/index.mjs
```

로그인이 없다면 `codex login` 후 브라우저에서 ChatGPT 계정으로 로그인합니다. 구독을 사용하려면 API 키 로그인으로 바꾸지 않습니다. [공식 인증 안내](https://learn.chatgpt.com/docs/auth)

일반 Windows 터미널에서 `codex`를 찾지 못하면 Codex 앱 터미널에서 실행하세요. 현재 앱이 관리하는 실행 파일은 `C:\Users\WonJeong Yu\AppData\Local\OpenAI\Codex\bin\bffc5354119c8421\codex.exe`입니다. 이 버전 폴더는 앱 업데이트로 달라질 수 있습니다. 배치 파일은 Node 대체 경로를 찾지만 Codex PATH 문제까지 해결하지는 않습니다.

`EADDRINUSE` 오류는 같은 포트에서 이미 서버가 실행 중이라는 뜻입니다. 기존 서버 창의 주소를 사용하거나 다른 포트로 실행합니다.

```powershell
$env:INNO_PORT = '4175'
node server/index.mjs
```

## 6. 첨부 연결과 기존 연구 앱

파일은 **파일 연결**, 폴더는 **폴더 연결**을 사용합니다. 지원 브라우저에서는 끌어놓기도 가능합니다. 원본은 선택한 위치에 그대로 남고 앱에는 이름·경로·크기·수정 시각 등의 참조만 저장됩니다. AI에 필요한 텍스트는 실행 시 일시 전달하며 답변·인용·요약·생성 결과는 작업 기록으로 저장합니다. 모델 제공자 측 처리는 해당 서비스 정책을 따릅니다.

- 새로고침·기기 변경·브라우저 종료로 메모리 연결이 사라지면 원본을 다시 선택합니다.
- 파일 선택은 이번 플랫폼의 권한입니다. Codex에 E: 폴더 읽기 권한을 주었다고 웹사이트가 자동 접근할 수는 없습니다.
- 링크 연결은 주소 기록입니다. 링크를 붙였다고 페이지 전문이나 PDF를 읽었다는 뜻은 아닙니다.
- 스캔 PDF는 OCR이 필요합니다. 현재 추출 경로는 OCR을 제공하지 않습니다.
- 원본 삭제·변경을 앱이 복원해 주지는 않습니다. 원본은 기존 연구 자료 백업 방식으로 관리합니다.

| 자료 | 현재 사용법 |
|---|---|
| TXT/Markdown/CSV/JSON | 파일 연결 후 텍스트 기반 조회 |
| PDF/DOCX/PPTX | 텍스트 추출; 레이아웃·이미지의 완전 이해를 보장하지 않음 |
| RefAtlas | **연구 자료 → RefAtlas / Prism JSON 연결**, 목록 JSON 선택 |
| Prism | Prism에서 내보낸 분석 JSON을 같은 버튼으로 연결 |
| HDF5/전자현미경 원시 자료 | Prism/Analytics에서 먼저 분석하고 결과 JSON·텍스트를 연결 |
| Scheduler/NanoLab/Ledger | 기존 앱에서 기록 관리; 현재 통합 화면은 링크 중심 |

RefAtlas 목록 예시 위치는 `E:\Python\INNO RefAtlas\data\index\catalog.json`입니다. 목록의 서지정보와 논문 전문은 다릅니다. 내용 비교에는 실제 원문 또는 초록 파일을 추가 연결하세요. 목록·분석 JSON 조회 결과도 세션에만 유지됩니다.

연결 참조 최대 5,000개, 문서 추출 최대 200,000자, PDF/압축 문서 30 MiB, PDF 100페이지 제한이 있습니다. 실행 입력은 자료 수와 전체 요청 크기 제한도 받습니다. 큰 폴더 전체를 한꺼번에 AI에 보내기보다 해당 작업의 자료만 선택합니다. 형식·용량 무제한 처리는 아직 구현되지 않았습니다.

## 7. 중단·재개·역할·사용량

- **일시정지**: 이후 계속할 작업에 사용합니다. 재연결 후 **이어서 실행**을 누릅니다.
- **작업 취소**: 해당 작업을 종료합니다. 현재 취소 상태는 재개할 수 없으므로 나중에 계속할 목적이라면 일시정지를 사용하세요.
- 서버가 갑자기 종료되어 **진행 중**으로 남으면 서버를 다시 켜고 해당 작업을 일시정지한 뒤 원본을 연결하여 이어서 실행합니다. 체크포인트 이후 계산은 다시 수행할 수 있습니다.
- 구독 한도에 도달하면 한도가 회복된 뒤 직접 이어서 실행해야 합니다. 무인 자동 재시도 스케줄러는 현재 없습니다.
- **긴 작업 이력**: 실행할 때마다 요청·사용자 지시·체크포인트·대화를 함께 보냅니다. 첨부 원본은 이와 별도로 20개·600,000바이트 한도를 따릅니다.
  - 96KB 이하는 그대로 보냅니다.
  - 96KB~384KB이면, 원문 조회가 가능한 실행기에서 이전 AI 답변을 원문 조회 표시로 바꿔 96KB 안에 들어갈 때만 그렇게 보냅니다. 아니면 '예산 초과'로 표시하고 잘라내지 않고 전문을 보냅니다.
  - 384KB를 넘는 경우:
    - 원문 조회가 가능한 실행기이고 검증된 재개 상태가 있으면, 이전 AI 답변을 원문 조회 표시로 바꿉니다. 그 결과가 384KB 안에 들어가면 그대로 실행합니다. 요청, 사용자 지시, 체크포인트, 최근 대화는 그대로 보냅니다.
    - 그래도 넘으면 AI를 시작하지 않고 '작업 이력 전달 상한 초과'로 멈춥니다. 자동 재시도는 없고 구독 사용량도 쓰지 않습니다. 필요한 요청과 결과만 담아 새 작업으로 나누어 진행하세요.
  - 요청·체크포인트와 새로 입력한 내용만으로 384KB를 넘으면 실행할 수 없습니다. 그래서 기록할 때 바로 거절하고 안내합니다. 한글은 한 글자에 3바이트라 약 128,000자부터 해당합니다. 여러 입력이 쌓여 합계가 넘는 경우는 실행할 때 위와 같이 멈춥니다.
  - 384KB를 넘는 필수 이력을 나눠 읽는 기능은 제공하지 않습니다.
- **문맥 전달 기록**: 작업 상세의 '저장된 재개 지점' 아래에 마지막 실행의 전달 방식이 바이트로 표시됩니다.
  - 전체 프롬프트는 작업 이력, 첨부 발췌, 지침·형식으로 나눠 보여줍니다. CLI 안의 도구 정의는 측정하지 않습니다.
  - 원문 조회가 가능한 실행이면, AI가 생략된 원문을 다시 읽은 횟수와 응답 크기(원문 재조회)도 표시합니다. 측정하지 못한 경우 '미측정'으로 표시합니다.
  - 실행이 두 번 이상이면 '실행별 문맥 전달'에서 같은 작업의 최근 10회를 나란히 볼 수 있습니다. 다른 작업과는 비교하지 않으며, 절감량을 추정해 표시하지 않습니다. 토큰은 실행기가 보고한 값만 보여줍니다.
- **에이전트 구성 → 편집**에서 최대 6개 역할을 편집할 수 있습니다. 역할 표시는 각 에이전트가 실제 실행되었다는 증거가 아닙니다. 단순 작업은 직접 수행하고 필요한 경우 하위 에이전트를 사용하도록 실행기에 지시합니다.
- 선택 카드에서 결정하면 결정이 기록됩니다. 다음 실행은 실행 버튼으로 시작합니다.
- **사용량**은 실행기가 반환한 토큰 수 중심입니다. ChatGPT·Claude 계정 전체의 실시간 잔여율 및 자동 최적 공급자 전환은 현재 완성되지 않았습니다. 확인 불가 표시는 0%라는 뜻이 아닙니다.

## 8. Claude Routine: 결과 반환 인증

결과 반환은 **INNO Workspace 전용 Claude 클라우드 환경 → API 자격 증명**으로 연결합니다. OAuth용 custom connector를 추가할 필요는 없습니다.

- 이름: INNO Workspace
- 허용된 웹사이트: inno-workspace-api.innokaist.workers.dev
- 유형: Bearer
- 헤더 이름: Authorization
- 접두사: Bearer
- 헤더 시크릿: 프로젝트 .inno/cloud-access-token.txt 값

Routine 편집에서 실행 환경을 INNO Workspace로 선택하고 Instructions를 [ROUTINE.md](ROUTINE.md)의 최신 계약으로 교체합니다. 저장소의 scripts/inno-mcp.mjs가 curl로 도구를 호출하며 인증은 Claude 프록시가 처리합니다. 토큰을 환경 변수·Routine 본문·GitHub에 넣지 않습니다.

Routine 호출 토큰(CLAUDE_ROUTINE_TOKEN)은 INNO가 Claude를 시작할 때 사용하고, 위 INNO 접근 토큰은 Claude가 INNO로 결과를 돌려줄 때 사용합니다. 서로 다른 토큰입니다.

최종 성공은 시험 작업의 결과가 INNO에 저장된 것으로 확인합니다. 세션 생성만 성공한 경우 결과 반환까지 연결된 것이 아닙니다. 설정 항목과 실제 검증 상태는 [CLAUDE-CONNECTION.md](CLAUDE-CONNECTION.md)를 확인하세요.

## 10. 기록 백업과 업데이트

**기록 내보내기** 또는 연결 설정의 **모든 기록 내보내기**로 작업 JSON을 보관할 수 있습니다. 원본 첨부는 포함하지 않습니다. 내보낸 기록에는 대화·결과가 있으므로 개인 자료로 취급합니다. 현재 가져오기는 **이 기기 보관** 모드만 지원하며 서버 DB로 자동 복원하지 않습니다.

로컬 파일 백업은 서버를 정상 종료한 뒤 `.inno` 폴더를 본인 전용 위치에 복사합니다. SQLite를 실행 중에 파일 하나만 복사하면 일관된 백업이 아닐 수 있습니다. `.inno`에는 개인 토큰도 있으므로 공개 저장소에 올리지 않습니다.

소스를 업데이트할 때는 본인이 수정한 파일을 먼저 확인하고 다음을 사용합니다.

```powershell
git status
git pull --ff-only origin main
node --test --test-isolation=none tests/*.test.mjs
```

Cloudflare는 git push만으로 자동 갱신되지 않습니다. GitHub Pages도 현재 수동 실행 워크플로입니다. 이번 환경에서 사용한 배포 도구는 다음과 같습니다. 이 명령은 **프로젝트 폴더의 Codex 터미널**에서 실행합니다.

```powershell
node .inno/tools/npm/package/bin/npx-cli.js --yes wrangler@4 deploy
```

`.inno/tools`는 Git에 포함하지 않은 임시 도구이므로 새 PC에는 없을 수 있습니다. 새 개발 환경은 Node.js와 npm을 준비한 후 공식 Wrangler 설치/실행 절차를 따릅니다.

## 11. 사용자가 할 일과 남은 개발 구분

지금 할 일은 개인 접속 토큰을 안전하게 보관하고, PC·휴대폰 클라우드 연결을 확인하며, AI 작업은 로컬 실행기로 시험하는 것입니다. 그 다음 Claude 계정에서 Routine과 인증된 커넥터가 가능한지 확인합니다.

다음은 사용자가 설정을 잘못해서 안 되는 기능이 아니라 추가 개발/검증이 필요한 항목입니다.

- 클라우드 작업을 로컬 Codex가 자동 처리하는 공통 실행 연결
- Claude Routine 인증 설정과 실제 결과 회수 검증 상태 확인

## 작업 기록 버튼을 누른 뒤 연결이 끊긴 경우

새 작업을 서버가 저장했지만 응답을 받지 못했다면, 같은 탭에서 같은 요청 내용·작업 종류·첨부 참조로 다시 보내세요. 동일한 재시도 식별자를 사용해 기존 작업을 찾습니다. 저장을 확인한 뒤 같은 내용을 새로 보내는 것은 별도의 새 작업으로 처리됩니다.

일반적으로 같은 탭을 새로고침해도 재시도 식별자는 유지됩니다. 요청 원문·파일 내용·인증 토큰은 이 재시도 보관함에 저장하지 않으며, 서버 주소/인증 연결로 구분된 해시와 임의 식별자만 저장합니다. 확인되지 않은 요청은 최대 16건입니다. 한도에 도달하면 기존 요청을 같은 내용으로 재시도해 저장 여부를 먼저 확인하세요.

탭을 닫거나 브라우저 세션 저장소가 차단/삭제되거나 서버 주소·인증 연결을 바꾸면 식별자를 잃을 수 있습니다. 이 경우 서버의 작업 목록부터 확인하세요. 요청 내용이나 첨부 참조를 바꾸는 경우에도 다른 요청으로 취급합니다. 저장소를 사용할 수 없는 환경에서는 현재 페이지의 메모리에서만 재시도 정보를 유지합니다. 이 기능은 자동 오프라인 전송 큐가 아니며, 후속 메시지는 작업 버전 충돌 검증을 계속 사용합니다.

개발 버전의 생성 재시도 처리는 서버와 웹 화면을 모두 업데이트한 뒤 적용됩니다. 서버를 먼저 반영하세요. 내보내기/가져오기는 재시도 식별자의 백업 수단이 아닙니다.

## 원본을 나누어 쓰는 협업

2026-09-27 하위 작업별 원본 재연결과 마스터 원본 검토를 활성화했습니다. Codex 원본 작업은 호환되는 데스크톱 연결기가 실행 중이어야 합니다. 이 PC에는 사용자 환경변수 INNO_SOURCE_DELEGATION_VERSION=1을 설정했습니다. 이미 열려 있던 터미널은 환경변수가 갱신되지 않을 수 있으므로 새 터미널에서 시작하거나 해당 창에서 같은 값을 설정하세요. 이번 구현은 Codex·Claude 자식 두 개를 사용하는 협업이며 유동적인 에이전트 수 최적화는 후속 단계입니다.

- 부모 작업에서 필요한 파일이나 폴더를 다시 연결하면 저장된 배정과 일치하는 하위 작업에도 연결이 적용됩니다. 하위 작업의 원본 배정 자체는 재연결로 바뀌지 않습니다.
- 상태 카드에서 필요한 원본과 배정된 제공자·모델을 확인합니다. 마스터 최종 검토에도 원본이 필요하며, 완료된 자식 결과만으로 원본 확인을 대신하지 않습니다.
- 실행 요청 뒤 응답을 받지 못한 경우 자동으로 같은 AI 작업을 반복하지 않습니다. 이전 실행 종료를 확인하고 작업 복구 후 다시 확인합니다. 저장소가 차단되거나 기록이 손상된 경우에도 중복 방지를 위해 전송을 멈춥니다.
- 새로고침, 기기 변경, 계정 변경 후에는 파일을 다시 연결해야 할 수 있습니다. PC가 꺼져 있고 원본이 그 PC에만 있다면 클라우드에서도 해당 원본을 읽을 수 없습니다.
- 현재 한 실행의 원본 전달은 최대 20개, 합계 600,000 UTF-8 바이트입니다. 부분 조회에도 별도 제한이 적용됩니다. 파일 형식이나 크기와 무관한 무제한 처리를 보장하지 않습니다.
- 다른 INNO 앱의 연결은 필요하지 않습니다. 완료된 자식 결과는 복구 과정에서도 보존하지만, 실제 사용 중인 구독의 한도와 실행 환경 가용성은 별도로 적용됩니다.
