# MCP 서버 형식 플러그인 설계 (CR-007 후속, 설계만)

작성일: 2026-10-07. 근거: docs/PROVIDER-PLUGIN-PROPOSAL.md PLG-01·02, docs/PLUGINS.md(스크립트 없는 Agent Skills 등록부, S3·S4), docs/PROVIDERS.md(실행기별 격리). 이 문서는 구현 전 설계와 사용자 결정 지점만 다룬다. 코드는 바꾸지 않았다.

## 1. 목표와 지금 상태
- PLG-01은 "Agent Skills·MCP 서버 형식 우선"이다. 지금은 Agent Skills 중 **스크립트 없는** 것만 받는다(SKILL.md와 .md/.txt, 프롬프트에 넣어 전달). MCP 서버는 등록할 수 없다.
- MCP 서버는 지시문이 아니라 **실행 중인 도구**다. 실행기가 서버의 도구를 호출하고, 서버는 네트워크·파일·자격 증명에 닿을 수 있다. 그래서 스킬과 같은 "검토 후 프롬프트에 넣기" 방식으로는 다룰 수 없고, 권한과 연결 방식을 따로 설계해야 한다.
- 공급망 위험(제안서 근거): MCP 서버에는 코드 서명 표준이 없고, 저장소 오염·도구 설명 변경(승인 뒤 설명을 바꿔 다른 일을 시키는 방식) 사례가 보고됐다.

## 2. 실행기별로 MCP를 붙이는 방법
| 실행기 | 붙이는 방법 | INNO가 실행별로 정할 수 있나 |
|---|---|---|
| Codex(이 PC) | `codex exec -c mcp_servers.<이름>.url=…`(원격) 또는 `command/args`(로컬 stdio). 지금은 로컬 서버 모드의 INNO 자체 MCP만 이렇게 붙인다. | 예. 실행 인자로 서버와 토큰 환경 변수 이름을 넘긴다. 도구 단위 허용 옵션은 Codex 판별로 확인 필요. |
| Claude Code(이 PC, S2 시범) | `--mcp-config <json>` + `--strict-mcp-config`(지정한 서버만). 도구는 `mcp__<서버>__<도구>` 권한 규칙으로 하나씩 허용. | 예. 지금은 MCP 서버가 있으면 첫 이벤트에서 실행을 멈추므로, 지원하려면 "승인한 서버·도구만 있는지" 검사로 바꿔야 한다. |
| Claude Routine(클라우드) | Routine 설정과 claude.ai 커넥터에서 사용자가 관리. | 아니오. INNO가 실행마다 서버를 더하거나 뺄 수 없다. 대상에서 뺀다(필요하면 사용자가 Routine 쪽에서 설정). |

## 3. MCP 서버의 두 형태와 위험
- **원격 서버(Streamable HTTP):** 서버 코드는 PC에서 돌지 않는다. 위험은 (1) 작업 내용·원본 발췌가 외부 서버로 나가는 것, (2) 응답에 담긴 프롬프트 주입, (3) 서버 토큰 보관이다.
- **로컬 서버(stdio, npx·uvx·실행 파일):** PC에서 사용자 계정 권한으로 임의 코드가 돈다. Windows에는 Codex·Claude Code가 쓸 OS 샌드박스가 없다(Claude Code 시범도 이 때문에 셸을 막았다). 패키지가 바뀌면 다른 코드가 돈다.

## 4. 설계 원칙(제안)
1. **허용 출처:** 공식 MCP 레지스트리의 항목이나 공식 벤더가 직접 배포하는 서버만 후보로 한다. 판(version)과 무결성 값(원격은 서버 URL·도구 목록 해시, 로컬은 패키지 무결성 해시나 실행 파일 해시)을 고정한다.
2. **권한 선언(manifest):** 형태(remote/stdio), 네트워크 대상 도메인, 파일 접근(none 또는 실행 폴더), 노출 도구 이름 목록, 필요한 비밀값 이름을 선언한다. 선언 밖은 실행기 인자로 막는다(Claude Code: `mcp__서버__도구` 허용 규칙만, 나머지 거절).
3. **도구 설명 고정:** 승인할 때 도구 이름·설명·입력 스키마 전문을 보여 주고 그 해시로 승인한다. 실행 시점에 서버가 알리는 도구 목록·설명이 다르면 그 서버를 빼고 사용 중지한다(설명 변경 공격 방지). 스킬의 "검토 해시 승인"과 같은 방식이다.
4. **원본 보호:** 연결한 원본 파일이 있는 작업에는 MCP 서버를 붙이지 않는다(원본이 외부로 나가는 길을 만들지 않음). 원본 없는 작업에서만 쓴다.
5. **비밀값:** INNO는 MCP 토큰을 저장하지 않는다. 필요한 서버는 사용자 PC의 환경 변수(또는 OS 자격 저장소) 이름만 manifest에 적고, 실행기는 그 이름만 넘긴다. 클라우드 Worker로는 보내지 않는다.
6. **비용 원칙:** 유료 API 키나 사용량 과금이 필요한 서버는 받지 않는다(기존 구독만 쓰는 원칙). 무료 공개 서버나 사용자가 이미 쓰는 서비스의 공식 서버만.
7. **기록:** 실행마다 붙인 서버·도구와 호출 횟수만 남긴다(호출 내용·응답은 남기지 않음). S4의 효과 근거와 같은 방식으로 보인다.
8. **끄기:** 사용 중지·삭제는 스킬과 같다. 해시가 바뀌면 즉시 사용 중지한다.

## 5. 단계 제안
- **M1(권장 첫 단계): 원격 서버, 읽기 도구만.** 예: 문헌 검색처럼 무료 공개 원격 서버. 원본 없는 작업에서 이 PC의 Codex·Claude Code 실행에만 붙인다. 도구 목록·설명 해시 승인, 선언 밖 도구 거절, 호출 횟수 기록. 로컬 stdio 서버는 받지 않는다.
- **M2: 로컬 stdio 서버(별도 결정).** 샌드박스가 없으므로 다음 중 하나가 정해져야 한다: (a) 공식 벤더의 서명된 실행 파일만, 해시 고정, (b) Windows Sandbox나 WSL 같은 격리 안에서만 실행, (c) 받지 않음.
- **M3: 추천·효과 근거 연결.** S4의 카탈로그 후보·효과 근거에 MCP 서버를 더한다(자동 설치 없음).

## 6. 구현 범위 추정(M1)
- 등록부: MCP 레코드(형태·URL·도구 목록 해시·선언 권한·상태), 가져오기(레지스트리 항목 → 도구 목록 조회 → 검토 화면), 승인·사용 중지·삭제.
- 실행기: Codex 실행 인자, Claude Code `--mcp-config`·허용 규칙과 시작 이벤트 검사 변경, 실행 시점 도구 목록 대조.
- 화면: 플러그인 대화상자에 "MCP 서버" 구역, 작업별 선택(원본 있는 작업에서는 고를 수 없음).
- 시험: 해시 불일치 시 제외, 선언 밖 도구 거절, 원본 작업 차단, 비밀값이 Worker·기록에 남지 않음, 적합성 스위트에 MCP 항목 추가.

## 7. 사용자 결정이 필요한 것
1. M1부터 시작할지(원격·읽기 도구만), 그리고 구현 우선순위.
2. 로컬 stdio 서버를 받을지와 받는다면 격리 방식(M2의 a·b·c).
3. 토큰이 필요한 서버를 받을지(무료 서비스라도 사용자가 토큰을 PC 환경 변수로 관리해야 함).
4. 원본이 있는 작업에서 MCP를 완전히 막는 원칙에 동의하는지.

## 8. 하지 않는 것
- Claude Routine 실행에 MCP 서버를 붙이는 것(INNO가 설정할 수 없음).
- 유료 API가 필요한 서버, 자동 설치, 승인 없는 도구 호출.
