# CR-010 제안: 원본 없는 작업의 클라우드(Claude Routine) 자동 배정

작성일: 2026-10-07. 상태: 제안(사용자 승인 대기). 근거: 최초 요구 "PC가 꺼져도 접근·연속 작업"(REQUIREMENTS-STATUS 최초 요구 대비 표), PRD의 재연결 대기 원칙, CR-006 제공자 레지스트리·PRV-06 사용 중지, H7 하위 작업.

## 1. 문제
- 지금은 사람이 작업마다 실행기를 고른다. Codex(이 PC)를 고른 작업은 PC 연결기가 켜져 있고 준비될 때까지 대기열에 남는다.
- 원본 파일이 없는 작업은 PC 없이 클라우드 Claude Routine으로도 실행할 수 있다. 그런데도 PC가 꺼져 있으면 휴대폰에서 시작한 작업이 몇 시간씩 멈춰 있을 수 있다.
- 원본이 연결된 작업은 원본이 PC에만 있으므로 지금처럼 PC를 기다려야 한다. 이 원칙은 바꾸지 않는다.

## 2. 제안
실행기 선택에 **"자동"**을 더한다. 자동은 원본이 없는 최상위 작업에만 적용한다.
- **시작할 때:** PC 연결기가 켜져 있고 해당 실행기가 준비돼 있으면 이 PC(Codex)로, 아니면 클라우드 Claude Routine으로 보낸다.
- **대기 중 전환:** 자동으로 시작해 PC 실행기를 기다리던 작업이 정해진 시간(제안 기본 10분) 동안 시작되지 못하면, 아직 실행되지 않은 상태에서 한 번만 Claude Routine으로 옮긴다.
- **결정 기록:** 어느 실행기로, 왜(연결기 오프라인·로그인 필요·사용 중지 등) 보냈는지 작업 기록에 남기고 화면에 보인다.

## 3. 지키는 원칙
1. **원본 보호:** 원본(첨부 파일·폴더)이 하나라도 있는 작업, 원본 위임을 받은 하위 작업은 자동 배정하지 않는다.
2. **이미 시작된 실행은 옮기지 않는다:** 실행 중이거나 시작 여부가 불확실한 작업(확인 필요)은 그대로 둔다. 실행 전 대기 상태에서만 바꾼다. 이미 실행된 뒤의 제공자 변경은 기존 인계 규칙(최대 두 번, 사유 필요)을 따른다.
3. **한 번만:** 자동 전환은 작업당 한 번이다. Claude가 한도 대기에 걸려도 다시 PC로 되돌리지 않는다(왔다 갔다 하며 두 구독을 소모하지 않음).
4. **사용자 설정 존중:** 사용 중지(PRV-06)된 실행기로는 보내지 않는다. 둘 다 쓸 수 없으면 지금처럼 대기한다.
5. **비용:** 기존 두 구독 안에서만. 유료 API·추가 사용량 없음. 자동 배정은 어느 구독을 쓸지 바꿀 뿐 추가 실행을 만들지 않는다.
6. **명시 선택은 그대로:** 사람이 Codex나 Claude를 직접 고른 작업, 마스터가 자식에게 배정한 제공자는 바꾸지 않는다.

## 4. 요구(안)
| ID | 요구 |
|---|---|
| ROUTE-01 | 원본 없는 최상위 작업에 "자동" 실행기를 고를 수 있고, 시작 시 사용 가능한 실행기(PC 우선)로 보낸다. |
| ROUTE-02 | 자동 작업이 PC 실행기를 정해진 시간 이상 기다리면, 실행 전 상태에서 한 번만 Claude Routine으로 옮긴다. |
| ROUTE-03 | 결정·사유·시각을 작업 기록에 남기고 화면에 보인다. 원본 작업·실행 중·확인 필요·명시 선택·자식 배정은 제외한다. |

## 5. 구현 범위 추정
- Worker: 실행 요청의 `provider: 'auto'` 해석(원본·사용 중지·연결기 준비 상태로 선택), 대기 중 전환은 예약 실행(5분 간격)에서 조건부 갱신으로 처리, 결정 기록 필드.
- 화면: 실행기 선택에 "자동 (PC가 꺼져 있으면 클라우드 Claude)", 작업 상세에 배정 결정 한 줄, 원본 작업에서는 자동을 고를 수 없음.
- 시험: 원본 작업 제외, 실행 중·확인 필요 제외, 한 번만 전환, 사용 중지 존중, 동시 시작과 예약 전환의 경합, 기록.

## 6. 사용자 결정이 필요한 것
1. 이 CR을 승인할지.
2. "자동"을 새 작업의 기본값으로 할지, 사람이 고를 때만 쓸지.
3. 대기 중 전환 시간(제안 10분).
4. 자동 작업에서 PC를 우선할지 클라우드를 우선할지(제안: PC 우선 — Codex가 원본 없는 일반 작업도 맡아 왔고, Claude Routine은 하위 작업을 한 번에 하나씩만 실행하므로).
