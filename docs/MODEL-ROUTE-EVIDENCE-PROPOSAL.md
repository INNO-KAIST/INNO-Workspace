# CR-004 제안: 구독 실행에서 실제로 가능한 모델 최적화 근거

작성일: 2026-09-28 (한국시간). 상태: 승인됨(2026-10-03 A안 선택, PRD 11절). 2026-10-05 구현(커밋 전) — docs/MODEL-ROUTING.md와 docs/superpowers/plans/2026-10-05-execution-route-evaluation.md 참고. 아래는 당시 제안 원문이다.

## 확인한 현재 상태
- HEAD f23f7f8, 최근 전체656개 통과. 초기 정책 자동 생성은 구현됐지만 자동 승격의 실운영 가능성을 증명하지 않는다.
- server/runners.mjs는 Codex에 지정한 model/effort를 기록하되 actualModelVersion:null. worker/review-observation.mjs는 알려지지 않은 실제 버전을 만들어내지 않으며 null로 귀속한다.
- public/core/model-selection.mjs의 승격은 non-null modelVersion의 동일 기준 비교를 요구한다. 이 조건은 승인 PRD의 '미관측 버전은 미확인으로 남긴다'보다 엄격하게 구현된 내부 선택이다. 사용자가 이 세부 제약을 별도 승인했다고 해석하지 않는다.
- review-observation의 비교 식별자에는 parent.id와 batchId가 포함된다. 현재 한 배치의 Codex/Claude 각1개 위임으로는 같은 제공자의 기준/후보 쌍이 생기지 않는다. 정상 관측이 쌓이면 자동으로 비교가 성립한다는 주장은 잘못이다.
- Claude 현재 Routine의 실행 모델과 요청 별칭은 같다고 보장하지 않는다. 별칭만 바꿔 절감했다고 판단할 수 없다.

## 선택 A: 실제 적용한 실행 경로를 평가 단위로 추가 (권장)
- 제공자 내부 serving version과 런너가 적용한 model/effort를 별도 필드로 유지. actualModelVersion은 공개된 신뢰 근거가 없으면 계속 null.
- CLI가 명시적으로 적용한 경로와 실행/세대/프롬프트 버전/도구 설정을 묶어 평가한다. 모델 스스로 말한 모델명은 근거로 사용하지 않는다. UI는 '이 실행 경로의 관측 결과'라고 표시하며 내부 버전 검증이나 전체 작업 동등 품질를 주장하지 않는다.
- 비교는 명시된 동일 입력/평가 기준/도구·문맥 조건을 가진 사례에 한정한다. 필요한 원본/선택 범위의 검증된 hash가 없거나 대화·환경이 다르면 비교 제외. 단순히 parent/batch ID를 지워 서로 무관한 작업을 짝짓지 않는다. 원문을 별도 영구 저장하지 않는다.
- 최소 표본·독립 검토 필수 기준 통과·중대 회귀 없음·실측 토큰 절감·지연 비악화·현재 계정 가용성 요구는 유지. 이미 승격된 모델 간 전환은 현재 경로와 직접 비교 가능한 근거도 필요하다. 수동 고정/철회 우선.
- 제공자/클라이언트/모델 설정 변경이나 근거 만료 시 자동 사용을 재검토한다. 숨겨진 내부 변경을 즉시 검출할 수는 없으며, 이를 명확한 한계로 표시한다.
- 추가 AI 비교 기본0 유지, 사용자가 허용한 비교만 실행. 선택 A 승인 자체는 비교 토큰 소비 승인이 아니다.
- Claude Routine에서 모델 제어/실행 경로 증거가 확보되지 않으면 자동 최적화 가능으로 표시하지 않는다. 검증 가능한 Claude 구독 실행 경로를 먼저 연결한다. 유료 API로 우회하지 않는다.
- 새 언어/빌드 도구/런타임 추가 없음. 강한 Windows 프로세스 격리 문제는 별도로 남아 있으며 이 선택으로 시간/과금 종료 보장을 주장하지 않는다.
장점: 현재 구독 실행에서 얻을 수 있는 근거를 이용한 최적화 구현이 가능하다.
단점: 제공자가 공개하지 않은 내부 버전 변경을 완전히 구분할 수 없어 평가 범위·만료·회귀 감지가 중요하다.

## 선택 B: 내부 실제 버전이 확인될 때까지 자동 승격 보류
- 현재 non-null serving version 요건 유지. 사용량 관측/초기 정책/고정·철회/수동 관리 및 일반 작업을 계속 제공한다.
- 제공자 실행 경로에서 필요한 증거와 비교 프로토콜을 확보할 때까지 자동 최적화는 보류로 표시한다.
장점: 버전 귀속의 엄격한 조건을 유지한다.
단점: 현재 연결된 구독 실행으로는 자동 승격이 작동하지 않으며 언제 가능해질지 확인되지 않았다.

## 결정 후 검증 계획
A 선택: PRD MOD01/03/04/05에 실행 경로 평가의 의미와 한계를 명시→런너 귀속/실행 조건 fingerprint→명시적 비교 사례/정상 관측 재사용 계약→자동 승격/CAS 및 현재경로 대비 절감→UI→독립 검증과 운영 릴리스. 원문/비밀/실제 모델 미확인을 감추지 않는다.
B 선택: 코드 승격 조건 유지, 실운영 보류 사유를 UI/가이드에 명시하고 나머지 플랫폼 과제를 진행한다.

## 공식 문서 대조
2026-09-28 조회: https://learn.chatgpt.com/docs/non-interactive-mode 는 exec JSONL 이벤트와 사용량, 저장된 CLI 인증 재사용을 설명한다. 예시에는 serving-version 인증이 없다. 이것만으로 모든 실행 인터페이스가 버전을 제공하지 않는다고 단정하지 않으며, 위 장애 진단은 현재 저장소의 실제 실행 경로에 대한 것이다.
https://learn.chatgpt.com/docs/developer-commands?surface=cli 는 실행 모델 선택 인터페이스를 설명한다. 모델 선택과 내부 제공 버전 입증을 동일시하지 않는다.

## 독립 감사 추가 확인
- model_policy_availability는 production 경로에 writer가 없고 현재 테스트 fixture만 값을 넣는다. Codex desktop_models는 요청 model/effort의 계정 노출 근거이며 capability/context/내부 serving-version 증명은 아니다. 선택 A 구현 시 이를 근거 수준별로 분리해야 한다.
- 정상 verifyReviewObservation은 quality.critical:false로 기록한다. fail/unverifiable 기준은 부정 품질 근거지만 현재 자동 중대 회귀 철회 신호를 만들지는 않는다. 실패를 모두 중대 오류로 바꾸지 않으며, 사전에 정의된 중대 오류의 독립 검증 계약을 후속 설계해야 한다.
- 추가 비교 예산0에서는 같은 입력·문맥에 대한 실제 자연발생 비교 사례가 없으면 A도 자동 승격하지 않는다. A는 근거를 위조하지 않고 실행 가능한 평가 단위를 추가하는 선택이며 즉시 토큰 절감이나 자동 승격을 보장하지 않는다.
