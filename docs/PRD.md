## 2. 범위 (In)

## 3. 비범위 (Out)
추가 유료 API·인프라, 원본 영구 업로드, 다른 INNO 앱 필수 연동, 무제한 파일 처리 보장. 이번 마일스톤만으로 전체 제품 완료를 선언하지 않는다. 후속 마일스톤은 유연한 에이전트 수/모델 최적화, 사용량 관측, 논문·Figure·CV·보고서·PPT 제작 품질, 모바일·장기 운영 검증이며 기존 REQUIREMENTS-STATUS.md의 미완료 범위를 유지한다.

## 6. 위험 및 가정
- 이번 작업으로 새 언어/빌드 도구/런타임이 추가되는가? **아니오**. 기존 JavaScript ES modules, Node 24, Python 검증 도구, Wrangler/Worker/D1을 유지한다. 필요성이 생기면 변경요청을 먼저 기록한다.
- 메모리 내 불확실 실행 기록만으로 새로고침·탭 소실 안전성을 입증할 수 없다. 서버 소유권/실행 식별자와 재조회 정책을 검증해야 한다.
- PC가 꺼져 로컬 원본에 접근 불가능하면 해당 작업은 재연결 대기한다. 무료 서비스/구독 한도와 Claude Routine 가용성은 외부 제약이다.
- 기존 혼합 제공자 배정은 2개 자식 고정 기반이다. 원래 요구한 유동적 에이전트 최적화의 완료 근거가 아니다.
- 397개 테스트 통과는 2026-09-21 기록이며 이번 재개 후 재실행 결과가 아니다.

Claude와 ChatGPT/Codex에서 새 모델과 성능 변화가 생겨도, 마스터가 하위 배정 전에 작업별 품질 기준과 최신 가용성·실측 근거를 확인하도록 한다. 구독만 사용하며 추가 유료 API를 도입하지 않는다. 다른 INNO 앱 연결 없이 동작한다.

## 설계 선택
공식 목록만으로 즉시 새 모델을 쓰는 방식은 계정 접근권한과 품질을 확인하지 못한다. 모든 신모델에 반복 AI 벤치마크를 돌리는 방식은 구독 사용량을 낭비한다. 따라서 공식 자료로 후보를 찾고 계정/실행 증거로 확인한 후, 정상 작업 관측과 제한된 평가로 작업군별 정책을 갱신하는 방식을 제안한다.

자동 판단의 근거가 모자라면 승격을 보류한다. 새 모델의 전체 작업 품질이 항상 동일하다고 보장할 수는 없으며, 평가를 통과한 작업군과 근거 범위만 명시한다. 별칭이 같은 상태에서 실제 모델이 바뀐 경우에도 실제 버전이 관측되면 새 후보로 분리하고, 관측되지 않으면 버전 미확인으로 남긴다.
