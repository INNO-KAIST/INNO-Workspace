# 최초 요구사항 대비 진행 현황 (2026-09-27)

전체 플랫폼은 아직 완료되지 않았다. 이 문서는 현재 목표와 검증 범위를 정리하며, 세부 시험 기록은 [VERIFICATION.md](VERIFICATION.md)에 보관한다.

## 유지할 원칙

- INNO Workspace는 독립 플랫폼이다. NanoLab·Prism·RefAtlas·Scheduler·Analytics·Ledger는 필요한 작업에서만 선택적으로 이용한다. 설치·계정·데이터 형식·연결이 핵심 작업의 필수 조건이 되어서는 안 된다.
- 기존 ChatGPT/Codex·Claude 구독을 사용한다. 추가 유료 API나 유료 인프라를 전제로 하지 않는다.
- 연결한 원본은 별도 영구 보관하지 않는다. 작업 이력·체크포인트·선택 범위 메타데이터·생성 결과물을 보관한다.
- 알려지지 않은 사용량·품질·완료 상태를 추정해 성공으로 표시하지 않는다.

## 현재 상태

사용자의 main 반영·Cloudflare 배포 승인과 PRD·검증 명령 승인을 받아 검증된 코드가 2026-09-27 main 및 Worker/Pages에 반영되었다. Node 427개·Python 4개, 실제 Codex 원문 검토와 실제 Claude 결과 반환을 확인했다. 원본 첨부 협업 게이트는 아직 비활성이며 실제 혼합 제공자 첨부 작업을 검증한 뒤 활성화할 예정이다. 전체 플랫폼 완료를 의미하지 않는다. 신규 모델 자동 최신화 CR-003은 별도 PRD 개정 승인 대상이다.

## 다음 작업 순서

1. Claude 및 혼합 제공자 실행의 실제 배정→검토→결과 회수→실패 복구를 검증한다. 승인되지 않은 운영 변경은 수행하지 않는다.
2. 선택 자료를 사용하는 협업 범위를 확대하고, 문서·Figure·발표자료의 실제 제작/검증 여정을 완성한다.
3. 모바일·데스크톱 동시 사용과 장기 실행·한도·재시작·저장 증가 시나리오를 검증한다.
4. 승인된 변경을 운영 반영한 뒤 원래 요구사항별로 완료 여부를 재평가한다.

## 최근 검증 근거

- 전체 Node 회귀 테스트 339개 통과. 캐시 입력 보고의 수집/저장과 일반 중단·종료 신호 실패·브리지 소유권 상실 시 중복 실행 방지 포함.
- PDF/Office 검사 도구의 기존 Python 테스트 4개 통과 기록이 있다. 이번 실행 중단 수정에서는 해당 도구를 변경하지 않았다.
- 실제 Codex PDF 시험의 입력 보고는 88,024, 출력은 848이었다. 당시 캐시 값은 수집하지 않아 복원할 수 없으며 절약 효과는 입증되지 않았다. 이후 실행부터 보고된 캐시 값을 보존한다.
- 위 회귀 테스트는 전체 플랫폼의 실사용 완료 증거가 아니다. 미보고 사용량은 확인 불가이며 계정 잔여량·비용으로 환산하지 않는다.

### 후속 동기화 검증

저장 응답을 받은 뒤 상태 조회만 실패하는 경우, 확인된 작업과 버전을 유지하고 조회 실패를 별도 표시한다. 이전 조회 응답은 확인된 저장을 덮어쓰지 못한다. 두 실제 로컬 HTTP 클라이언트의 연결 단절·오래된 수정 거절·재연결 수렴을 검증했으며 전체 Node 테스트 344개를 통과했다. POST 응답 자체 유실의 멱등 처리, 실제 휴대폰/데스크톱 동시 사용 검증은 남아 있다.

### 생성 응답 유실의 중복 방지

생성 요청의 UUID와 정규화한 최초 내용 해시를 작업에 연결해 SQLite/D1 재전송 시 같은 작업의 현재 상태를 반환한다. 같은 식별자의 다른 내용은 충돌 처리한다. 브라우저는 같은 탭의 세션 저장소에 원문 없이 해시·식별자 최대16건을 보관한다. 로컬 HTTP 응답 유실 후 클라이언트 재생성 시험을 포함해 전체352개 테스트 통과. 탭/저장소 소실, 연결 또는 내용 변경과 후속 메시지의 응답 유실은 별도 범위다. 운영 반영은 아직 대기 중이다.

### 첨부 협업 착수

일반 첨부도 실행 자료에서 누락·중복되거나 다른 자료가 섞이면 공통 검증에서 거절한다. Codex 프로세스 시작 전 거절을 포함한 전체354개 테스트 통과. 원문 비보관 하위 작업 협업의 설계/실행 계획은 `docs/superpowers/plans/2026-09-21-transient-source-delegation.md`에 있다. 현재는 선행 자료 완전성 검증만 구현되었고, sourceIds 배정·자료 대기·하위 실행·마스터 원문 재검토·자동 재연결은 이어서 구현해야 한다.

### 자료 선택 배정 계약

서버 내부 버전 설정이 켜진 경우에만 sourceIds로 부모 첨부 참조를 선택하고, 하위 작업에 정제한 메타데이터만 배정하는 기반을 추가했다. 범위 해시와 배정 재전송을 보존하며 저장 실패는 원자적으로 되돌린다. 전체361개 테스트 통과. 현재 실행 환경은 이 설정을 켜지 않으므로 첨부 협업 기능은 아직 비활성이다. 자동 실행기의 자료 대기 처리·직접 하위 실행·검토 원문 전달·재연결 UI가 다음 구현 범위다.

### 자료 대기 및 직접 실행 기반

자료가 필요한 작업은 자동 실행기가 대기 상태를 바꾸거나 빈 원문으로 시작하지 않으며, 뒤의 자료 없는 작업은 계속 처리한다. 내부 설정을 켠 시험 환경에서 두 제공자의 하위 작업·마스터 검토에 원문을 일시 전달하는 경로를 연결했다. 전체371개 테스트 통과(제공자 모의 응답). 현재 기본 실행 환경은 비활성이며 계획 지침 연결·원본 재연결 UI·실제 구독 실행 검증은 남아 있다.

### 마스터 자료 배정 지침 연결

내부 기능 설정이 켜진 경우 Codex·Claude 마스터에 정제된 자료 ID/범위 참조와 원문 비보관 배정 지침을 전달한다. Codex 배정 결과의 미등록 자료 ID는 전달 전에 거절하며 서버 상태에서 지원 버전을 확인할 수 있다. 전체376개 테스트 통과(모의 제공자). 데스크톱 실행기와의 지원 버전 일치 및 브라우저 재연결 연결은 남아 있어 기본 기능은 계속 비활성이다.

### 데스크톱 지원 버전 확인

서버와 데스크톱 실행기가 공통으로 지원하는 첨부 협업 버전만 사용한다. 미지원 실행기는 첨부 하위 작업을 점유하기 전에 거절되며, 브라우저가 보낸 값으로 로컬 지원 범위를 높일 수 없다. 전체382개 테스트 통과. 실제 활성화 전 브라우저 자료 재연결·자동 전달·불확실한 시작 응답 복구가 남아 있다.

### 브라우저 자료 준비 공통화

일반 실행 버튼을 공통 자료 읽기·검증 경로에 연결했다. 읽기 전 개수/연결 상태를 확인하고 비동기 읽기 중 작업 버전이나 연결 서버가 바뀌면 전송하지 않는다. 실제 파일의 선택 범위·내용 변경 검증을 포함해 전체388개 테스트 통과. 하위 작업 자동 전달 조정 기능은 이 경로를 재사용하도록 이어서 구현해야 한다.
